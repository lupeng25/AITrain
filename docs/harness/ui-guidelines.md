# 界面实现规范

## 信息架构

本轮用户已批准 [工作台重设计方案](../design/ui-workbench-redesign.md)。该方案取代此前“固定九个并列导航入口”的界面约束。

日常导航只有数据集、训练、模型。顶栏提供项目菜单与任务记录；环境与诊断、设置属于工具入口。验收报告从模型页进入。内部可以保留独立页面索引，不要求内部路由数量等于侧栏按钮数量。

保留 Qt Widgets、侧栏、顶栏、中央 `QStackedWidget`、AppStyle、Sidebar、InfoPanel、StatusPill。没有常驻检查器。业务页面通过单层目录、详情或操作模式切换；不再叠放多层标签或整页滚动。

## 状态与边界

- MainWindow 只负责壳层、导航及控制器协调。
- Widget 拥有布局和视觉状态；Controller 拥有表单、操作上下文和命令构造。
- 持久化事实来自 Query Service / Presenter；写入由 ProjectWorkspace / Worker 完成。
- 项目切换清理旧对象身份和异步读取上下文。异步结果必须验证对象身份与代次，避免晚到结果覆盖当前对象。
- 切换日常导航不重新初始化训练草稿；数据目录中浏览其他对象不自动改变训练绑定。
- 目录搜索通过 Query/Presenter 的 `CatalogFilter` 覆盖全项目元数据，条件绑定分页游标；不能只筛选已加载行。输入去抖后刷新，搜索不能扫描用户文件内容。
- 草稿按持久化 ProjectId 存放在应用设置，最大 256 KB，版本化保存稳定控件值。恢复必须重新核对四重数据身份及样本成员；未应用的高级编辑保存其原值，不能自动启动或 Resume。
- 浅色和深色由 AppStyle 与 QPalette 统一管理；图表、状态、弹窗和禁用态必须随主题可读。语言由 Qt 翻译资源管理；静态文案经过 `WorkbenchTranslation.h` 或 Qt `tr()`，协议值和用户数据不翻译。
- 四元快照身份必须来自同一条已提交记录。普通表单不要求用户填写 UUID。
- 不增加 Resume、动态插件或运行时自动回退，不改变官方后端和部署能力边界。

## 尺寸与滚动

主要验证窗口为 1280×820 和 1366×768，按 Qt 逻辑像素检查。最小窗口为 1024×700。侧栏保持可读文字；字号不能为了适配而无限缩小。

目录表格、日志、报告阅读器可以自身滚动。基础表单保持短小，主要操作按钮固定在可见区域。高级参数使用一个分组导航和一个内容栈，每次显示一个分组。

路径、模型名、状态和项目名必须允许收缩；长标题省略并提供完整提示。长报告不应撑开整个主窗口。

## 统一视觉

采用中性浅色工作区、细边框、蓝色主操作。颜色和中文状态同时表达含义。所有样式由 AppStyle 维护；表格统一为只读、整行单选、隐藏行号。

没有结果时显示未运行、尚未统计、尚未读取或失败原因，不用零值、固定通过状态或示例曲线填补空白。Artifact 的清单未读取不等于零文件；数据快照文件数不等于样本数。

普通页面优先显示名称、日期、类型和状态；完整 ID、哈希和技术参数保留在技术详情或专用工具中。来自数据、文件和日志的文本按纯文本显示；报告阅读器不自动加载外部资源。

## 训练与结果

训练目录、配置、监控、高级参数和完整日志分别显示。当前产品没有通用参数 schema；本轮保留原参数控件与后端映射，按现有约定校验，不能描述成自动生成了新的参数合同。

高级参数取消必须恢复编辑前的值。取消任务后显示正在取消，直到 Worker 返回实际终态。历史对象不受另一任务的活动更新覆盖。

训练、质量检查、模型导入、运行验证和 OCR 工具的终态要回到原操作上下文。报告必须定位到对应对象的已提交产物，不能只跳转到无选择的全局任务页。

## 验证

代码变更运行 `tools/harness-check.ps1`。UI 回归在 `tests/tst_delivery_acceptance_ui.cpp` 中验证三入口、单层模式、路径边界、草稿保持、质量结果和窗口按钮边界；可通过 `AITRAIN_CAPTURE_UI_DIR` 输出各页面模式截图进行人工检查。测试截图或 smoke 不替代外部硬件和客户精度验收。
