# AITrain Studio 界面重设计方案

日期：2026-09-08。状态：用户已批准；2026-09-12 本轮界面迁移和验收已完成，见[实施记录](ui-workbench-implementation.md)和[最终收尾记录](ui-workbench-closeout.md)。

说明：第 13 节记录的是方案形成时的交付和检查。本次实施的最终结果以 Harness 当前状态和新增验收记录为准，不以交互示意代替产品验收。

## 1. 设计结论

将九个并列工作区收敛为三个日常入口：**数据集、训练、模型**。项目切换放在顶栏，任务记录放在全局入口，环境和设置放在工具区。用户围绕当前数据集、训练任务或模型操作，无需先判断一个功能属于哪个技术模块。

取消当前业务页整页长滚动、页内多层标签、常驻检查器、重复身份表单、重复主按钮和固定示例状态。目录占据主工作区；查看对象时用详情替换目录，返回后恢复选择和位置。一次只显示当前操作所需的表单。

这是一套新的信息架构和交互规格，不沿用当前九页的视觉方案。保留 Qt Widgets、左侧导航、顶栏、中央 `QStackedWidget`、独立 Worker 以及现有存储和能力合同。现有 `ui-guidelines.md` 中“固定九页”的规定，后续实施时依据本次用户授权更新；本提案没有修改该文件。

交互示意中的项目、数量、模型指标和运行状态均为示例，不是当前项目验收结果。

## 2. 范围和证据

方案基于当前分支 `codex/v3-final-closeout`、提交 `7a97dd8` 的 Harness、页面/控制器、类型化 Worker 命令、训练 Profile 和 Runtime Delivery 工作流，并参考本轮实际 Windows 界面诊断。

诊断中实际复现的问题包括：重开项目后首次进入数据集目录为空、切换页面覆盖模型选择、质量任务成功后原页仍等待、两张图片被显示为五个样本、报告三个文件被显示为零，以及环境明细与顶栏 GPU 状态不一致。新界面必须同时消除这些状态和数据投影问题。

方案形成阶段只新增此设计文档、会话内交互示意及其验证材料。当时没有调整代码与 Harness；用户批准后的实际改动及验证见[实施记录](ui-workbench-implementation.md)。

## 3. 新的信息架构

```text
启动：最近项目 / 打开项目 / 新建项目
打开项目后
├─ 顶栏：当前项目 ▾                         任务记录   环境状态
├─ 左侧导航
│  ├─ 数据集
│  ├─ 训练
│  ├─ 模型
│  └─ 底部：环境与诊断 / 设置
├─ 中央：当前目录，或当前对象的详情，或当前操作表单
└─ 底部活动条：仅有活动任务或需要处理的终态时出现
```

| 原入口 | 新位置 | 用户看到的内容 |
|---|---|---|
| 总览 | 启动界面；打开项目后不再占日常导航 | 最近项目和继续工作入口；不做指标卡墙 |
| 项目 | 顶栏项目菜单 | 创建、打开、项目概况、重建索引等已有操作 |
| 数据集 | 数据集 | 目录、样本、质量结果及数据操作 |
| 训练实验 | 训练 | 训练记录、新训练配置、训练详情 |
| 任务与产物 | 全局“任务记录” | 所有任务、状态、日志和可定位的产物 |
| 模型库 | 模型 | 模型目录、模型详情和导入 |
| 部署验证 | 模型的“验证与交付”操作 | 样本选择、受支持路线、结果和报告 |
| OCR 验收与外部证据 | 模型页工具菜单“验收报告” | 官方报告导入、OCR 验收、外部验收证据；允许没有模型绑定的报告 |
| 环境 | 全局环境状态；底部“环境与诊断” | 按能力解释可用性、检查明细、诊断包 |
| 系统设置 | 底部“设置” | 环境路径、Worker 配置、语言、许可及已有设置 |

**导航深度规则**：常规路径只有“目录 → 对象详情”。操作表单替换当前内容或打开一层对话框；不在详情中再嵌套标签页，不从一个对话框叠开另一个业务对话框。高级参数和报告查看器按专用工具处理，关闭后回到原上下文。

**全局任务入口**是临时进入中央工作区的工具视图，提供“返回工作区”；不常驻占用训练、数据集或模型页面的一半空间。返回后恢复原对象、草稿和分页游标。

## 4. 布局与信息密度

### 4.1 尺寸预算

产品按逻辑像素设计，主要验收视口为 1280×820，补充 1366×768 和 1920×1080。

| 区域 | 建议尺寸与行为 |
|---|---|
| 左侧导航 | 176–192；1280 宽度仍保留图标和中文，不自动变成纯图标 |
| 顶栏 | 高 48–52；长项目名省略，完整名称在项目菜单中查看 |
| 工作区边距 | 20–24；紧凑模式 16；保持统一间距 |
| 页面标题与工具栏 | 总高约 64–80；一个主要按钮，最多两个常用次要动作 |
| 活动条 | 高 32–36；状态一行；详细日志进入任务详情 |
| 目录表 | 默认行高 40，紧凑模式 34；内容区域随窗口伸缩 |
| 基础表单 | 宽 680–820；最多两列，常用输入框宽度不小于 220 |
| 简单对话框 | 宽 560–680；2–6 个基础输入；底部确认/取消始终可见 |
| 高级参数编辑器 | 宽 880–1000；单层分组导航，右侧一次显示一个分组 |

建议验收最小产品工作区为 1024×700；不足该尺寸时优先保持文字、按钮和表单可用，可显示窗口过小提示。不能通过把字号和输入框缩小到难以阅读来适配。Windows 缩放按实际可用逻辑尺寸检查，不把 1280 物理像素误当作 1280 逻辑像素。

### 4.2 滚动规则

1. 目录、训练基础配置、常规对象概况不使用包住整页的 `QScrollArea`。
2. 目录只在表格自身滚动；底部提供“上一页/下一页”，基于现有游标分页。未知总量不显示虚构页数。
3. 对象详情最多一个主要可滚动区域；必要时表格、长日志或报告各有自己的专用阅读视图。
4. 同一内容块只允许一层滚动，不出现“窗口滚动条 → 面板滚动条 → 表格滚动条”。
5. 高级参数通过切换单层分组控制长度；底部应用/取消固定。不要把全部高级参数折叠堆在基本配置下方。
6. 长报告保留阅读器自身滚动和查找；不能要求报告本身也强行一屏显示。

### 4.3 视觉规范

整体使用中性浅色工作区、清晰的文字导航、细分隔线和单一蓝色主操作。支持按同一令牌生成深色外观。颜色承载选中和状态，不用不同颜色的大卡片区分每个模块。

正文建议 14，辅助文字 12–13，标题 20–22，输入和按钮高 32–36。状态必须同时有中文标签；“成功”“存在问题”“失败”“尚未检查”不能只通过颜色判断。长技术名称允许换行，路径提供截断显示、完整查看和复制。

继续由 `AppStyle` 统一维护；统一 `QTableView` / `QTableWidget` 规则及对象名。保留 `Sidebar`、`InfoPanel`、`StatusPill`，重设计其外观及组合方式，避免在每页重新实现一套容器和徽标。

## 5. 数据集

### 5.1 默认目录

页面标题“数据集”，主要按钮“导入数据”。表格默认五列：名称、任务/格式、当前版本、样本数、质量状态。更新时间可放到对象详情或宽屏可选列。

单击选择整行；“查看样本”打开详情；双击也可打开，但不能依赖用户知道双击。选中对象后显示与其有关的动作：**用于训练、检查质量、更多**。没有对象时不显示要求填写 ID 的空表单。

目录支持名称查找和现有查询能力允许的筛选；若当前 Query 没有完整搜索接口，实施时补齐 Query 投影，不能仅过滤已载入的第一页并宣称全库搜索。第一批可先交付完整游标分页，再增加搜索。

空态为“还没有数据集”，一个“导入数据”按钮和支持格式说明。加载中、读取失败、筛选无结果、确实为空四种状态分开表示。

### 5.2 导入短流程

1. 点击“导入数据”，选择源文件夹或当前合同允许的源文件。
2. 填写可读名称；格式自动探测，可显式更改；选择新数据集或当前合同允许的现有目标。
3. 显示将建立项目快照的简短摘要，再点击“导入”。名称和格式错误在字段旁提示。
4. Worker 执行期间显示活动条；可以关闭表单并浏览其他对象。当前单活动任务约束仍然生效。
5. 成功且提交后刷新目录并选中新快照；显示“检查质量”和“用于训练”。失败或取消保留来源和输入内容，不显示未提交对象为可用。

用户只输入有业务意义的内容。`DatasetId`、`DatasetVersionId`、`SnapshotId`、`ArtifactId` 由已选择记录生成，不允许跨记录拼接。

### 5.3 对象详情

顶部为“返回数据集”以及“名称 / 版本”。主体是样本预览与简短说明，默认没有标签栏。宽屏可采用预览约 2/3、说明约 1/3；较窄时说明压成顶端两行摘要。

样本通过现有快照中的安全成员查询得到，显示文件名、尺寸及实际可解析的标注。样本列表按需读取；无法解析时显示原因和可查看的文件信息，不能始终保留空画布而提示“已加载”。示意中绘制的样本不构成新增图片格式或标注渲染能力承诺。

版本选择器与名称相邻。切换版本同步切换样本、质量结果和后续任务身份。质量状态点击后进入同一对象的质量阅读模式，通过明确“返回样本”退出；没有叠加的第二层标签页。

### 5.4 低频操作的位置

| 操作 | 表单与结果 |
|---|---|
| 检查质量 | 默认使用当前快照；高级检查选项按需打开；完成后直接呈现结论、问题表和报告 |
| 划分数据 | 当前快照只读；目标名称、划分比例、已有选项；展示实际任务返回的新版本/快照 |
| 格式转换 | 选择源目录和受支持目标格式、目标名称；沿用转换命令的源路径边界，不假装已有快照到快照转换接口 |
| 修复与标注 | 从质量问题或修复清单进入；选择外部工作目录和工具摘要，创建标注会话 |
| 同步标注结果 | 从现有会话选择器进入；读取会话产物身份，显示同步后的实际结果 |
| 样本复核 | 从相关质量/修复结果打开样本复核阅读模式；保留现有问题筛选和打开样本能力 |
| 技术详情 | 只读展示身份、校验摘要、来源和审计信息；提供复制 |

“修复与标注”沿用当前外部标注会话工作流，不承诺新增内置绘制编辑器。不同操作共享同一个对象选择器，但不合并成一个无法预测行为的“运行质量工作流”按钮。

## 6. 训练

### 6.1 训练目录

默认表格列为训练名称、数据集版本、模型/任务、状态、开始时间。主要按钮“新建训练”；运行中的记录置于可见位置，但不改变用户正在查看的历史对象。

训练页不常驻配置栏。点击记录进入详情；新建训练时中央区域切换为宽配置表单。切换导航只切换视图，不重新装填模型预设。

### 6.2 新建训练

基础表单按能力动态显示，目标为六至八项，不能给八个后端强行塞同一套不适用参数：

| 字段 | 行为 |
|---|---|
| 数据集和版本 | 由数据集页进入时预选；内部同时绑定同一快照四元身份 |
| 任务/算法 | 从数据格式和编译期能力合同筛选；可读名称优先；后端作为简短说明 |
| 模型/预训练权重 | 只列当前任务支持的预设，允许合同已有的自定义输入 |
| 训练轮数 | 当前后端支持时展示；默认值来自 schema，不统一硬编码 |
| 批次大小 | 同上；错误时给出字段级说明 |
| 输入尺寸 | 同上，遵守当前任务的尺寸结构 |
| 计算设备 | 使用现有可验证设备信息；信息不足时显示待检查 |
| 其他必需配置 | OCR 配置等后端必填项替换不适用字段，避免追加成长表单 |

训练显示名优先从当前对象和时间生成，允许后续补齐显示元数据后编辑；不为名称单独新增训练协议参数。交付检查所需样本从已绑定快照中选择并显示文件名；如果合同要求且不能可靠自动选择，必须作为独立必填行，必要时采用“基础配置 → 检查并启动”两步短流程，不能藏在高级参数里。

底部提供“高级参数”“取消”“开始训练”。开始前只列当前能力确有影响的阻塞项，例如没有已提交快照、缺少对应 Python 环境、非法参数、Worker 正忙。未运行过质量报告不应被 UI 擅自变成额外的训练硬门槛；以现有合同和工作流校验规则为准。

**高级参数**使用宽编辑器，按当前 schema 形成单层分组，例如数据与加载、优化、增强、验证与导出、其他。每次显示一个分组；保留字段类型、范围、默认值和说明。应用前统一验证，取消不改变草稿。不通过窄栏中的原始 JSON 作为默认配置方式；原有可用 JSON 入口可放在专家工具中。

### 6.3 训练详情

顶部一行显示名称、真实状态和主动作；下一行显示当前阶段、进度和已用时间。中间主要区域显示当前任务确实返回的指标曲线。指标不存在时显示“该后端未提供此指标”，不能填零或画示例曲线。

页面底部保留小范围最新日志预览以及“完整日志”。完整日志进入专用阅读模式，工具栏固定；切回后保留日志位置。配置、原始事件、产物与审计均通过明确动作查看，不再永久挤占监控区域。

| 状态 | 主动作与呈现 |
|---|---|
| 草稿 | 开始训练；显示字段和必要的前置检查 |
| 运行中 | 取消任务；显示来自 Worker 的当前阶段和指标 |
| 取消请求已发出 | “正在取消”；等待真实终态，不立即显示已取消 |
| 成功 | 查看模型 / 查看报告；只有产物实际提交后才启用 |
| 失败 | 显示失败阶段和原因；查看日志、复制配置新建训练 |
| 已取消 | 显示实际保留的产物和终态；允许复制配置创建新任务 |
| 状态待核对 | 重新查询持久化状态；不能把进程中断直接显示为成功 |

不引入 Resume，不将“复制配置新建训练”表达为断点续训。切页、返回和打开任务记录都必须保留未提交配置；跨应用重启的草稿恢复不作为第一阶段承诺。

## 7. 模型

### 7.1 模型目录与详情

默认列为名称、任务类型、来源、模型格式和最近验证状态。主要按钮“导入模型”。选择模型后提供“查看详情”“验证与交付”“更多”；不要求用户先进入另一个全局部署页面再重复选模型。

模型详情只显示能够从包和关联记录读取的模型摘要、训练来源、数据版本、有效指标、已有报告。指标必须带验证集或报告来源。不同任务不统一使用 mAP，也不能把一次成功的单样本推理称为精度验收通过。

### 7.2 导入模型

采用两步短流程：选择模型文件与已有 Manifest；再检查模型家族、任务、输入输出、解码器和产物入口。已有 Manifest 可直接解析并校验。辅助结构化填写与 `manifestDraft` 适配属于新界面工作，必须复用现有 Contract 验证；未知模型不能自动猜测为兼容。

高级用户保留原始 Manifest 查看/导入方式。普通界面不显示整块空白 JSON 作为唯一路径。导入成功后选中新模型，显示可用的下一步动作。

### 7.3 验证与交付

把现有“部署验证”和“推理验证”两个发出同一命令的入口合并为一个动作。表单只要求：模型、运行路线、数据集版本、样本；模型从上下文预选，样本用文件名或缩略图选择。基准预热、迭代等保留在高级选项。

沿用当前六步 `RuntimeDeliveryCommand`：解析模型、验证 Manifest、推理冒烟、基准测试、部署验证、生成交付报告。界面将阶段显示为简短进度，展开才查看技术步骤。不能另写一套 UI 内推理流程。

结果模式首先显示真实执行结论，再显示可用的 overlay、性能事实和交付报告。失败应突出失败阶段和修复方向；没有返回 overlay 时解释原因。报告入口直接定位 `TaskId + ArtifactId + relativePath`。

| 能力 | 界面边界 |
|---|---|
| YOLO 检测/实例分割 | 训练、首次 ONNX 导出、评估使用官方 Ultralytics；AITrain C++ 路线按当前包合同、构建和环境判断；已支持的 ORT/NCNN 不等于任意模型包都可运行 |
| YOLO OBB | 产品部署 v1 仅 ONNX Runtime；不提供可执行的 NCNN/TensorRT 选择 |
| SMP 语义分割 | SMP 官方适配路线，AITrain ONNX Runtime；不承诺 NCNN/TensorRT 导出与运行 |
| PatchCore / EfficientAD | Worker 管理 Python/Anomalib 产物和既有工作流结果；不伪装成通用 C++ Runtime Delivery 支持 |
| PaddleOCR Det / Rec / System | 官方训练和报告验收边界；在验收报告工具中操作，不冒充通用 C++ OCR 部署 |
| TensorRT | 区分导出能力与当前 C++ 解码未实现等运行状态；说明具体阻塞原因，不回退其他运行时 |

模型页可以查看训练 Profile 已产生的导出结果。当前协议没有独立的通用导出任务，不把“重新导出为任意格式”纳入本轮 UI 改造承诺。新增导出入口必须另立后端任务范围。

### 7.4 验收报告工具

保留官方 Det、Rec、System 报告导入；使用报告选择器绑定三份相关报告，然后运行现有 OCR 验收。保留 cohort、客户域、证据类别和阈值字段，用两步短表单组织。没有对应证据就显示缺失，不能因为任务执行成功而宣称客户域 OCR 已达标。

外部验收证据导入放在同一工具中；不强制虚构 ModelPackage 归属。报告可以按证据类和项目归属查看。诊断包采集另置于环境与诊断。

## 8. 全局工具

### 8.1 任务记录与产物

任务表展示所有现有工作流，默认列为操作、对象、状态、开始时间、耗时。活动任务始终可定位。选中记录进入任务详情，首屏是结论与结果入口，原始事件只放在“技术详情”。

产物默认列出包名称/用途以及由可靠摘要得到的文件数和大小。尚未加载的字段显示“未读取”或“—”，不能显示零。打开包再按需读取文件列表；大文本分块读取，图片按需加载。返回时保留任务、产物、文件与阅读位置。

活动条是入口，不是另一套状态系统。业务页面、活动条和任务详情使用同一任务投影。终态通知说明对应对象，点击直接打开结果；不可将关键提示写到隐藏的 statusBar。

### 8.2 项目

首次启动直接进入项目入口。已打开项目后，顶栏菜单提供项目概况和已有操作。项目概况用短信息列表显示路径、数据集、任务和模型等事实，不额外增加首页大卡片。

打开已有项目后立即恢复持久化目录；不能依赖用户先访问某页完成初始化。切换项目需使旧项目异步结果失效。存在活动 Worker 时按现有规则阻止冲突操作并给出明确原因。

重建等已有维护操作仍有独立确认，明确作用项目、预期影响和执行进度；不能作为普通页面刷新副作用触发。

### 8.3 环境与诊断

顶栏显示简短环境状态，例如“已检查 · 有缺失项”，不能用一个绿色“就绪”覆盖不同后端的依赖差异。环境详情按任务能力列出可用性、阻塞原因和最近检查时间。

设备信息只使用实际检查结果。报告生成成功与训练环境齐备分别表示。选择了某训练后端后，其前置检查复用同一环境事实，结果过期或信息不足时允许重新检查。

诊断包采集、外部证据入口及原始报告保留可达。设置使用单层类别列表：常规、运行环境、许可、关于/能力；每次只显示一个类别，不嵌套更多标签。

## 10. 状态与数据实现规格

### 10.1 所有权

| 责任 | 唯一所有者 |
|---|---|
| 导航、当前项目入口、全局工具入口 | App Shell / MainWindow |
| 草稿、字段联动、命令构造、当前对象选择 | 页面 Controller / 明确的会话状态对象 |
| 已提交数据、任务历史、产物与报告摘要 | Presenter + `ProjectQueryService` |
| 运行期进度、取消请求和 Worker 连接状态 | `TaskRuntimeController` |
| 持久化写入、工作流与产物提交 | `ProjectWorkspace` / Worker / `ProjectStore` |
| 字体、颜色、布局控件状态 | Widget + `AppStyle` |

不让多个 Label 独立维护“运行中/完成”。任务终态到达后，先按既有协议核对持久化记录与可用产物，再统一刷新相关对象投影。页面尚未创建时允许更新状态；创建或 attach 时必须渲染当前状态。

### 10.2 必须补齐的界面数据适配

1. **友好名称**：当前导入审计名称未必是目录可查询字段。先核对持久化来源；不足时通过 ProjectWorkspace/ProjectStore 补齐展示元数据及 Query，或明确使用来源目录/任务与时间生成名称。不能截断 UUID 冒充名称。
2. **样本数**：不能复用文件数。先显示“未统计”；从已有 manifest/质量报告读取真实样本数量，不足时增加明确的统计投影。文件数保留自己的名称。
3. **产物统计**：区分摘要未知与实际零值；优先使用持久化摘要，没有摘要就按需加载并显示读取状态。
4. **选择器**：数据集/版本/快照/样本、模型、报告和标注会话均复用分页 Query；选择一条有效记录后传递整体身份。
5. **报告定位**：页面动作携带任务、产物与成员路径，复用安全读取；不得返回 committed 物理路径给 GUI。
6. **异步代际**：项目切换、对象切换时递增 generation；迟到结果不得污染当前页面。
7. **草稿**：导航不调用重置默认值。只在用户明确改变会使现值失效的能力/格式时重算相关字段，并提示被改变的项。
8. **可用性**：命令可执行性由能力合同、环境、模型兼容性和 Worker 状态共同决定；禁用动作显示具体原因。

以上属于确保新界面可用的必要工作。其中展示元数据的完善可能涉及存储投影或兼容迁移；它们不改变训练算法或现有运行时边界，但必须单独评审和验证，不能被笼统归为“只改样式”。

## 11. 分阶段实施计划
